How to use these notes

A suggested workflow

Read → recall → code

  1. Read the definitions first. Discrete maths is notation-heavy. If you can state a definition precisely, most exercises become mechanical.
  2. Cover the worked example and redo it. Every example in these notes comes from the lecture handouts — try it on paper before reading the solution.
  3. Translate to Python. The module tests whether you can read and execute code, so trace the code patterns by hand and predict the output.
  4. Finish with the cheat sheet. Use it for spaced repetition, not as a first introduction.

What the exam rewards

  • Precise use of symbols: \(\in\), \(\subseteq\), \(\to\), \(\forall\), \(\exists\).
  • Correct truth tables and membership tables, row by row.
  • Knowing the difference between similar ideas: subset vs. proper subset, converse vs. contrapositive, permutation vs. combination.
  • Reading Python and stating what it computes — not writing large programs from scratch.
  • Justifying counting answers, not just quoting a formula.

The five big ideas

Each topic builds on the previous one. The diagram below is the mental map; keep it in mind as you revise.

01

Compute, don't calculate

Recognise when a task is repetitive and hand it to a machine. Python is the concrete notation for the algorithms.

02

Precision beats intuition

Natural language is ambiguous. Logic gives statements an exact truth value and rules for combining them.

03

Structure shapes operations

Sets are unordered and unique; lists are ordered; dictionaries map keys to values. The structure determines what you can do.

04

Relations are the glue

A relation is a set of ordered pairs. Functions are the well-behaved relations where every input has exactly one output.

05

Count the choices

Most counting problems reduce to a sequence of decisions. Identify the decisions, then add or multiply.

∑

Connect the topics

Set cardinality feeds counting; Cartesian products feed relations; bijections feed permutations. Nothing stands alone.
